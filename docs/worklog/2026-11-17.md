# 작업 기록 — 2026-11-17

## 1. 행사 상세 참여자 정보 수정

행사 상세의 참여자 "상세보기" 모달에 **수정** 모드를 추가했다. (`PUT admin/rotation/event/{id}/members/{memberId}`, 라우트명 `members.update`)

### 수정 가능 / 불가

| 구분 | 항목 | 비고 |
|---|---|---|
| 수정 가능 | 핸드폰, 출생연도, 키, 직업, MBTI, 지역, 흡연, 주량, 음주 횟수, 친구 약속, 애완동물, 이상형·장점·취미·TMI, 음료(1:1) | 회원 본인 입력/프로필 값 |
| 수정 가능(최고관리자만) | 비밀번호 | 기존 정책(비밀번호는 최고관리자만 열람). 비우면 유지. 일반 관리자가 값을 보내도 서버가 무시 |
| 수정 가능(규칙 있음) | **번호표 · 성별** | 아래 "번호표·성별 변경 규칙" 참고. 체크인 명단과 함께 바뀐다. |
| 수정 불가 | 테이블 | 체크인 화면의 "번호·테이블 변경"에서만 변경 |
| 수정 불가 | 신청 플랫폼 | 관리자 라벨은 체크인 명단의 플랫폼을 우선 사용하므로 회원 값만 바꿔도 화면에 반영되지 않는다. |

### 번호표·성별 변경 규칙 (`MemberProfileService::changeIdentity`)

번호표(`members.name`)와 성별은 체크인 명단(`event_rosters`)과 (행사, 성별, 번호표)로 연결되고, 좌석·로테이션 이동(여자 고정/남자 이동)·투표 대상(이성)·관리자 라벨이 이 값에 의존한다. 그래서 아래를 모두 한 트랜잭션에서 검증·반영한다.

- **중복 거부:** 바꾸려는 (성별, 번호표)를 체크인 명단의 다른 행 또는 다른 회원이 쓰면 거부. (번호를 맞바꾸려면 한쪽을 먼저 다른 번호로 바꿔야 한다)
- **명단 동기화:** 연결된 체크인 명단 행의 번호표·성별도 함께 변경. 연결 행이 없는 과거 회원은 회원만 변경.
- **성별 변경 제한:** 투표·메시지 기록(보낸/받은)이 있으면 거부. 기록이 이성 기준으로 쌓여 있어 같은 성별 사이의 기록이 생기기 때문.
- **1:1 테이블 제약:** 바꾼 성별이 이미 그 테이블에 앉아 있으면(좌석 또는 체크인 명단) 거부. 테이블당 같은 성별 1명 원칙 유지.
- **로테이션 시작 후:** 성별을 바꾸면 자리 이동 방식이 달라져 현재 자리가 바뀐다. 허용하되 모달에 경고 표시.
- **숫자가 아닌 예외 회원 이름:** 번호표 입력을 비활성화하고 성별만 변경 가능.
- 번호표 범위 1~999(`RosterService::TICKET_MAX`).

### 문제될 수 있는 부분과 처리

- **핸드폰 중복:** `(event_id, phone)` DB 유일 제약. 본인 제외하고 행사 안에서 검증하며, 삭제(soft delete)된 회원 행도 제약에 걸리므로 같은 규칙으로 확인. 하이픈은 제거 후 `010`+8자리 검증. 핸드폰은 참가자 로그인 아이디이고 만남 이력(번호 기준) 연결에 쓰이므로 화면에 경고 문구 표시.
- **체크인 명단과의 값 불일치:** 입장등록은 키·출생연도·직업을 체크인 명단에서 복사하고, 상세페이지/명단 이미지는 명단을 읽는다. 회원만 고치면 두 값이 어긋나므로 같은 트랜잭션에서 명단 행에도 반영(`RosterService::syncProfileFromMember`). 비어 있는 값은 명단을 지우지 않는다.
- **음료 변경:** 이 행사에 등록된 음료만 허용(1:1 행사만). 바뀌면 `MemberDrinkChosen`을 커밋 후 발행해 행사 상세의 선택 현황이 실시간으로 갱신된다.
- **동시 수정:** 회원 행을 `lockForUpdate`로 잠그고 트랜잭션 안에서 저장.
- **과거 회원 호환:** 일부 값이 비어 있는 회원이 있어 필수는 핸드폰만. 비워서 저장하면 해당 값을 비운다. 선택지 값(주량 등)은 정해진 목록만 허용.
- **로그인 세션:** 핸드폰/비밀번호를 바꿔도 이미 로그인한 참가자의 세션은 유지된다. (다음 로그인부터 새 값)
- **저장 후 갱신:** 표·뱃지·음료 현황이 모두 서버 값으로 다시 그려지도록 페이지를 새로고침한다.

## 4. 음료 전달 완료 체크 (1:1)

- 행사 상세 "음료 선택" 현황에서 사람(번호표 칸)을 누르면 **전달 완료**로 체크, 다시 누르면 해제. 완료 칸은 초록 + 체크 아이콘 + 전달 시각(HH:mm). 미선택 목록은 체크 불가.
- 카드 상단에 `전달 N/M`, `전달 대기 N명`, 음료별로 `전달 N/M` 뱃지(모두 전달하면 초록).
- 다른 관리자 화면도 실시간 갱신: `MemberDrinkServed` 이벤트(같은 채널 `event-drinks.{eventId}`, 이벤트명 `drink.served`). Reverb가 없으면 체크한 화면만 즉시 다시 불러온다.
- 데이터 정합성:
  - 음료를 고르지 않은 회원은 체크 불가(서버 검증).
  - 관리자가 회원의 음료를 바꾸면 전달 완료를 해제(`MemberProfileService::update`).
  - 음료를 목록에서 삭제하면 그 음료를 고른 회원의 전달 완료도 해제(`RotationService::eventDrinkSync`).
  - 이미 체크된 상태에서 다시 체크 요청이 와도 처음 체크 시각을 유지.
- DB: `members.drink_served_at` (timestamp, nullable) — 마이그레이션 `2026_11_17_100000_add_drink_served_at_to_members_table`
- 라우트: `PATCH admin/rotation/event/{id}/members/{memberId}/drink-served` (`members.drinkServed`)
- 파일: 신규 `Events/MemberDrinkServed.php`, `Requests/Admin/Rotation/EventMemberDrinkServedRequest.php`, 마이그레이션 / 수정 `Member.php`, `MemberProfileService.php`, `RotationService.php`, `EventController.php`, `routes/admin.php`, `eventForm.blade.php`, `_drinkPeople.blade.php`
- 배포 전: `php artisan migrate`

## 6. 기존 행사에 기본 음료 한꺼번에 추가

- 행사 생성 이후(또는 생성 후 1:1로 바꾼) 행사는 기본 음료가 자동으로 들어가지 않으므로, 음료 목록 설정에 **"기본 음료 추가 (6종)"** 버튼 추가.
- 누르면 `EventDrink::DEFAULT_NAMES` 중 목록에 없는 것만 기존 목록 뒤에 붙여 확인 후 바로 저장. 이미 있는 음료와 참가자 선택·전달 체크는 그대로.
- 모두 있으면 안내만 하고, 최대 개수(30)를 넘으면 들어갈 수 있는 만큼만 넣고 알린다.
- 기본 음료 목록은 서버 상수 하나(`EventDrink::DEFAULT_NAMES`)를 행사 생성과 이 버튼이 함께 쓴다.
- 파일: `eventForm.blade.php`

## 7. 음료 가나다 정렬 · 설정 버튼 배치

- 음료를 **가나다(이름) 순**으로 표시: `EventRound::drinks()` 정렬을 `sort_order` → `name`으로 변경. 행사 상세 설정 카드·선택 현황, 참가자 입장등록의 음료 카드, 관리자 수정 모달의 음료 선택 모두 이 관계를 쓰므로 함께 바뀐다. 설정 화면에서 새로 추가한 음료도 클라이언트에서 `localeCompare('ko')`로 정렬. (`sort_order` 컬럼은 남아 있지만 표시 순서에는 쓰지 않음)
- DB 정렬 규칙(collation)에 따라 영문·괄호가 섞인 이름의 순서가 조금 다를 수 있다. 한글 음절끼리는 가나다 순.
- PC에서 "최대 30개" 문구와 "기본 음료 추가" 버튼이 좌우 양끝으로 벌어져 보이던 배치를 정리: 문구는 입력칸 아래 안내 한 줄, "기본 음료 추가"는 하단으로 옮겨 "음료 목록 저장"과 같은 폭으로 나란히(모바일은 위아래).
- 파일: `EventRound.php`, `eventForm.blade.php`

- **행사 상세** 메뉴 신규: 라우트 `GET admin/rotation/event/current`(`admin.rotation.event.detail.current`) → 지금 운영할 행사(진행 중 > 가까운 예정 > 최근, 체크인 메뉴와 같은 기준 `EventContextService::currentEventId`)의 상세로 이동. 행사가 없으면 행사 생성으로.
- 메뉴 활성 표시: `행사 목록`은 목록·생성만, `행사 상세`는 `event.detail*`, `체크인`은 `event.checkin*`·`checkin*`. (전부 `event*`로 잡으면 같은 깊이에서 목록이 먼저 걸려 상세/체크인에서도 목록이 활성화되므로 좁힘)
- 브레드크럼: 상세는 메뉴 경로로 자동 표시되므로 덧붙이던 `breadcrumbCurrent`를 생성 화면에만 남김.
- 권한: 새 라우트는 기존 금지 목록에 없으므로 기본 허용. 막아야 하는 역할이 있으면 "페이지 권한 목록"에서 추가해야 한다.
- 파일: `app/Enums/Menu.php`, `routes/admin.php`, `EventController.php`(`eventDetailCurrent`), `eventForm.blade.php`

## 11. 행사 생성 화면 반응형 개편

- 상세와 같은 뷰(`eventForm.blade.php`)를 쓰지만 생성 폼을 따로 구성: 모바일은 한 줄에 하나씩, PC(768px↑)는 2열.
  - 행사명: 한 줄 전체, 큰 입력칸.
  - 타입: 셀렉트 → **큰 토글 버튼**(1:1 소개팅 보라 / 와인파티 빨강, 높이 48px). 기본값은 첫 타입(1:1).
  - 일시: 큰 입력칸, 키보드가 뜨지 않게 `readonly`(달력으로만 선택).
  - 테이블 수: **−/+ 스테퍼**(0~100, 범위 밖 입력은 보정).
  - 리뷰 인증 게이트: 스위치 터치 영역 확대.
- 안내는 한 행에 한 문장. "1:1 소개팅은 기본 음료 6종이 함께 등록" 안내는 1:1을 골랐을 때만 표시.
- 하단 버튼: 모바일은 `행사 생성`(위)·`취소`(아래) 전체 폭, PC는 오른쪽 정렬. 생성 확인 창에 행사명·타입·일시·테이블 수를 보여주고, 요청 중에는 버튼 비활성(중복 생성 방지).
- 상세(수정) 폼에 남아 있던 쓰이지 않는 생성용 분기를 정리. 상세 폼 동작은 그대로.

## 13. 체크인 목록 카드 UI 개편

- 남/여 목록 머리: 뱃지 나열(`참석 n · 등록 n · 전체 n`) → 제목 `👨 남 · 명단 N명` + **참석 / 입장등록 / 미도착** 3칸 숫자(항목명 함께).
- 참여자 카드 3단 구성:
  1. **번호표 박스**(성별 색, 큰 숫자 · 없으면 "번호 미배정") · 닉네임 + 플랫폼/테이블 뱃지 · 오른쪽 **상태 하나**(미도착 / 입장등록 대기 / 입장등록 완료). 기존의 참석 뱃지와 입장등록 뱃지를 한 상태로 합침.
  2. **항목명 : 값** 정보 — 프로필(년생 · 키 · 직업, 없으면 "미입력" 빨강), 장점, 시각(체크인 HH:mm · 입장등록 HH:mm).
  3. 버튼 — `체크인`/`체크인 취소`(PC에서도 표시), `프로필`, `번호·테이블`(체크인 후 입장등록 전), `삭제`(미도착만, 오른쪽 끝). 모바일은 체크인/취소가 한 줄 전체, 나머지는 2열 같은 폭.
- 카드 전체 탭으로 체크인/취소, 각 버튼 동작·클래스는 그대로 유지.
- 안내 문구를 한 행에 한 문장 + 상태 흐름 설명으로 정리.
- 파일: `checkin.blade.php`

## 19. 로테이션 진행 테이블 카드: 몇 호가 어디 있는지 한눈에

- 원인: 사람 칩이 `닉네임(플랫폼)_N호 97년생 · 직업` 한 줄 + 말줄임(`text-truncate`)이라 좁은 칸에서 **번호표(N호)가 잘려 안 보였음**.
- 변경: 사람 1명 = 한 칸 — 왼쪽 **큰 `N호` 배지**(성별 색) · 오른쪽 닉네임(플랫폼) / 년생·직업 두 줄. 말줄임 없이 줄바꿈. 남/여 칸 안은 **번호표 순** 정렬.
- 테이블 제목 글씨 크게(`N번 테이블` · 인원), 칸 머리 `남 n명 / 여 n명`.
- 제거(✕) 버튼 터치 영역 확대(1.6rem). 동작은 그대로.
- 배치: 모바일 1열 / 768px↑ 2열 / 1200px↑ 3열. (처음 4열까지 늘렸다가 PC에서 칸이 좁아 닉네임이 단어마다 줄바꿈되며 들쭉날쭉해 보여 조정)
- PC(992px↑)에서는 닉네임·년생직업을 한 줄로 두고 넘치면 말줄임, 마우스를 올리면 전체 내용(title). 번호(N호)는 왼쪽 배지라 잘리지 않음. 모바일은 줄바꿈 유지.
- 파일: `seating.blade.php`
- 추가(체크인 카드): **입장등록 완료**인 사람은 체크인 취소가 서버에서 막혀 있으므로 `체크인 취소` 버튼을 숨김(카드 탭 시 기존 안내 팝업은 유지). 모바일 2열 버튼 줄에서 보조 버튼이 홀수 개면 마지막 버튼을 한 줄 전체로 늘려, `프로필` 버튼 혼자 반쪽만 차지하던 문제 해결.

## 28. 모바일 이미지 다운로드 화질 (기기별 캡처 배율)

- 증상: 모바일에서 받은 상세페이지/피드 이미지가 PC보다 흐림.

- 조치: `computeSafeScale()`이 기기별 상한(`canvasLimits()`)을 먼저 정하고 그 안에서 가장 큰 배율로 바로 그림.

  - 안드로이드/기타 모바일: 면적 6,400만(메모리 부족 방지)
  - 데스크톱: 기존과 같음(면적 2억 5천만, 한 변 16,000)
  - 1배조차 한계를 넘는 아주 긴 장은 한계에 맞춰 1배 미만으로 줄여 빈 이미지 방지.
- 한계: PC와 같은 화질은 아님(기기 한계 안에서 최선). 같게 하려면 서버 렌더링(헤드리스 Chrome)이 필요 — 미적용.
- 검증: 실기기 확인 필요(iPhone Safari·안드로이드 Chrome에서 다운로드 후 해상도 비교).
- 파일: `detail.blade.php` (상세페이지 다운로드·피드 다운로드 공통, 체크인 명단 이미지도 같은 코드 사용)

## 29. 운영 리스크 보완 (회고록 P1·P2) — `docs/retrospective-risk-handling.md` 반영

- **입장등록 반쪽 데이터:** `MemberAuthController::register` 에서 `Member` + `RotationSeat` 생성을 `DB::transaction` 으로 묶음. 로그인·세션·음료 브로드캐스트는 커밋 뒤.
- **매칭 시작/마감 중복:** `SeatingService::openVoting/closeVoting` 이 행사 행 `lockForUpdate()` 후 상태를 확인. 이미 매칭중/종료면 거부(브로드캐스트·리포트 안 나감). `SendCloseVotingReportJob` 에 `ShouldBeUnique`(행사 ID).
- **번호표 유니크:** 마이그레이션 `2026_11_17_140000_add_unique_ticket_to_members_table` — `UNIQUE(event_id, gender, name)`. 적용 전 중복 점검 0건. 소프트 삭제 회원도 대상(기존 phone 유니크와 동일).
- **메시지 5회·투표 3명 제한 원자화:** `sendMessage`/`saveVotes` 가 트랜잭션 + 회원 행 락 후 재확인.
- **로테이션 연타 방지:** 관리자 화면이 확인창 전 턴�� `expected_round` 로 보내고, `rotateProgress` 가 락 안에서 비교해 다르면 거부(값이 없으면 기존 동작).
- **WebSocket 유실 보정:** `AppLayout` 이 연결이 끊겼다가 복구될 때, 5초 이상 가려진 탭이 돌아올 때 `router.reload()`. 진행 중 요청이 있으면 건너뛰고 최소 3초 간격.
- 미적용(P3): 실패 Job 알림, Redis 통일, 로테이션 자동 진행. 자동 테스트는 보류 — `phpunit.xml` 의 sqlite 격리가 꺼져 있고 `MemberPurgeTest` 가 실제 DB 회원을 지우므로 **`php artisan test` 실행 금지**.

## 32. 입장등록: 종교 · 이상형 조건 · MBTI · 성별 색

- 새 컬럼(마이그레이션 `2026_11_17_160000_add_religion_and_preference_fields_to_members_table`): `religion`(string), `outer_preference`·`inner_preference`(**json 배열, 다중 선택**). 모두 nullable.

## 34. 1:1 "어필" 탭 (매칭 결과 뒤 한 번 보내는 메시지)

- 1:1 소개팅 하단 탭에 **어필**(항상 노출). 이용은 종료(X) 뒤에만 — 종료 전에는 🔒 안내만 보이고, 종료/되돌리기 때 화면이 자동 갱신. 와인파티는 탭·화면 없음(홈으로).
- 내용: 서로 매칭되지 않은 이성 전체 대상, **전체에서 1통**(`Message::NOTE_MAX_SENDS`, 보낸 회원 행 락), **익명 아님**(받는 사람에게 "N호님의 어필"). 안내 문구에서 "익명" 표현 없이 "내 번호표가 함께 보여요"만.
- 기존 `messages` 테이블·읽음·실시간·안읽음 뱃지를 그대로 사용(구분 컬럼 없음 — 1:1 행사의 회원 메시지는 모두 어필). 라우트 `GET/POST /notes`, 화면 `Pages/Notes.jsx`, `MessageSender`/`SendModal` 이 익명 여부·주소·문구를 받도록 확장(기본값은 기존 동작).
- 관리자가 보낸 메시지도 어필 화면에 "📢 관리자"(노란 카드)로 표시. 종료 전에도 볼 수 있음. 메시지 조회 모달의 관리자 메시지도 노란 배경으로 변경.
