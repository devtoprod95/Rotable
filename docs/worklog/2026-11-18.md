## 1. 체크인: 입장등록 완료자 회원 상세보기

- 체크인 카드에서 **입장등록 완료**(`registered`)인 사람에게만 [회원 상세보기] 버튼 표시. 누르면 행사 상세와 같은 `_memberDetailModal`(수정 포함)이 열린다.
- 체크인 명단과 회원은 외래키 없이 **(행사, 성별, 번호표)** 로 연결된다. `RosterController::rosterList` 응답에 `member`를 추가했고, `memberDetailsByTicket()`이 회원 목록을 `"성별|번호표"` 키로 만든다. (`label`·`age`·`last_login_at`, 최고관리자는 `password` 포함)
- 입장등록 완료 카드는 눌러도 **아무 동작 없음**(체크인 취소 안내창 제거, 커서·눌림 효과 제거). 카드 안 버튼(프로필·회원 상세·회원으로 로그인)은 그대로 동작.
- 체크인 남/여 명단 머리글을 눌러 **접기/펼치기**(상태는 localStorage에 기억).
- 파일: `RosterController.php`, `checkin.blade.php`

## 2. 관리자 "회원으로 로그인" (대리 로그인)

- 위치: 행사 상세 참여자 카드, 체크인(입장등록 완료자), 로테이션 진행 참여자 칸(아이콘 버튼).
- 동작: `POST admin/rotation/event/{id}/members/{memberId}/impersonate` → 새 탭에서 그 회원의 홈. **회원(web) guard만** 바꾸므로 관리자 로그인은 유지되고, 이미 로그인된 다른 회원은 덮어쓴다. 세션에 `admin_impersonating=true`를 남긴다.
- **기록 안 남김:** `last_login_at` 갱신 안 함, 메시지(`markMessagesRead`)·요청 답장(`reply_read_at`) **읽음 처리 안 함**(읽음 브로드캐스트도 없음). 하단 탭의 안 읽은 숫자도 메시지함·요청 화면에서 지우지 않고 유지.
- 회원 화면 header에 노란 **"관리자 대리 로그인 중"** 표시(`HandleInertiaRequests`의 `adminImpersonating`).
- 표시는 회원이 직접 로그인·입장등록·로그아웃하면 사라진다.
- 접속 마감(6번)도 대리 로그인 세션은 건너뛴다.
- 파일: `EventController.php`(`eventMemberImpersonate`, `eventMemberShow`), `routes/admin.php`, `_memberDetailModal.blade.php`(공통 클릭 처리), `eventForm/checkin/seating.blade.php`, `MemberPageController.php`, `MemberAuthController.php`, `HandleInertiaRequests.php`, `AppLayout.jsx`

## 3. 마지막 로그인 시각

- `members.last_login_at`: 회원이 **직접** 입장(로그인)하거나 입장등록한 직후 기록. 대리 로그인·이미 로그인된 세션 재방문은 기록하지 않는다.
- 표시: 행사 상세 카드("접속"), 체크인 카드, 회원 상세 모달. 행사 상세 정렬에 **최근 접속 순 / 오래된 접속 순** 추가(기록 없음은 가장 오래된 것으로 취급).
- DB: 마이그레이션 `2026_11_18_100000_add_last_login_at_to_members_table` (**배포 전 `php artisan migrate`**). 컬럼 추가 전 가입한 회원은 다시 로그인하기 전까지 "기록 없음".

## 4. 관리자 화면 개선

- **행사 상세 참여자 목록**을 체크인처럼 **남/여 두 칸**으로 분리(PC 좌우, 모바일 위아래). 성별 탭을 고르면 그 칸만 넓게. 정렬은 칸마다 따로. 버튼 줄은 줄바꿈(모바일 가로 스크롤 원인 보정), 카드 열은 `minmax(0,1fr)`.
- **로테이션 진행**: 참여자 칸에 아이콘 버튼 2개(상세 / 회원으로 로그인). 상세는 `GET .../members/{memberId}`(`members.show`)로 모달용 데이터를 불러온다.
- **메시지 조회 모달**: 보낸 사람(전체/남/여/관리자)·읽음 여부(전체/읽음/안읽음)를 **라디오 버튼 그룹**으로, 선택 즉시 조회. 서버 필터 `from`(`RotationService::eventMessageList`), 실시간 수신에도 같은 필터 적용. 목록은 PC에서도 **1열**, 모달 폭은 `modal-lg`.
- **개발 도구**: [더미 원스텝] — 더미 명단 추가 → 더미 체크인 → 더미 입장등록을 한 번에 실행(단계별 진행 표시, 실패 시 중단·사유 표시). 기존 개별 버튼과 같은 API.
- 파일: `eventForm/checkin/seating/_messagesModal.blade.php`, `EventMessageController.php`, `RotationService.php`, `SeatingController.php`

## 5. 참가자 명단 이미지: 모집중 자리 규칙

- 남/여 중 많은 쪽이 **10명 미만**이면 선택 없이 **양쪽 10줄까지** 모집중으로 자동 채움.
- **10명 이상**이면 "추가 안 함 / 1자리 / 2자리"를 고른다(기본 2). 남/여 줄 수는 항상 같게.
- 체크인 [참가자 명단 이미지]: 대상(전체/참석자)·2열 선택에 따라 안내·선택 가능 여부가 바뀐다. 주소 파라미터 `recruitExtra`(0~2), 옛 `recruit=0/1`도 호환.
- 상세페이지 제작 [체크인 명단 불러오기]: 명단을 가져온 뒤 10명 이상이면 추가 여부를 한 번 더 묻는다. 취소하면 명단을 바꾸지 않는다.
- 파일: `checkin.blade.php`, `detail.blade.php`
- 상세페이지 샘플에서 **"오픈 기념 할인 진행 중" 배너 삭제**(`_detailSample.blade.php`). 맨 아래 CTA의 "오픈 기념 할인 · 마감 임박" 문구는 남겨 둠. 이미 저장된 상세페이지에는 영향 없음.

## 6. 종료 행사 접속 기간 제한 (행사 후 2일)

- 기준: **행사 일시 + 2일**(`EventRound::MEMBER_ACCESS_DAYS`), **종료(X)된 행사에만** 적용. 진행 중이거나 아직 종료하지 않은 행사는 제한 없음.
- 로그인 시 거절("접속 가능 기간(행사 후 2일)이 지나 …"). 로그인 화면 행사 목록도 같은 기준.
- 이미 로그인한 회원은 `EnsureMemberAccessAllowed` 미들웨어(`auth:web` 그룹)가 **다음 요청에서** 회원만 로그아웃시키고 로그인 화면으로 보낸다. 관리자 로그인·대리 로그인은 유지. 화면을 열어 둔 경우 카운트다운 0에서 자동 새로고침으로 걸러진다.
- 회원 화면 상단 **카운트다운**: "⏰ 접속 가능 시간 1일 05:12:33 남음 · 이후 접속 불가"(서버 시각 기준, 1초 갱신, 1시간 미만이면 빨강) + "🔒 마감 후 입력하신 개인정보와 모든 데이터는 안전하게 폐기될 예정이에요." header → 카운트다운 줄 → 안내 줄이 둥근 모서리로 겹겹이 이어지고, 이때 header는 불투명 흰색.
- 와인파티·1:1 공통(타입 구분 없음).
- 테스트: `/login?all=1`로 종료 후 2일이 지난 행사까지 전체 목록을 보고(`[접속 마감]` 표시) 거절 안내를 확인. 운영에서는 관리자로 로그인한 브라우저에서만 동작. 테스트 후 `MemberAuthController::showLogin`에서 제거 가능.
- 중간에 종료 시각(`closed_at`) 기준으로 바꿨다가 요청에 따라 **행사 일시 기준으로 되돌림**. 컬럼·마이그레이션은 남기지 않았다.
- 파일: `EventRound.php`, `EnsureMemberAccessAllowed.php`(신규), `routes/web.php`, `MemberAuthController.php`, `HandleInertiaRequests.php`, `AppLayout.jsx`

## 알려진 제약

- 접속 마감은 **종료(X)된 행사**에만 적용. 종료를 잊은 행사는 2일이 지나도 막히지 않는다. 마감 시각은 행사 일시 기준이라 늦게 종료해도 변하지 않는다.
- 화면의 "개인정보·데이터 폐기 예정" 문구에 대응하는 **자동 삭제 작업은 없다**(`php artisan data:purge`는 수동 실행). 마감 후 정리 방법을 정해야 한다.
- 접속 마감 검사는 요청 시점에 일어난다. 화면을 열어 둔 상태는 카운트다운 0에서 자동 새로고침 때 걸러진다.
- 이미 로그인된 세션으로 다시 들어온 경우 `last_login_at`은 갱신되지 않는다(로그인 폼·입장등록 시점만).
- 세션 유지 시간은 `.env`의 `SESSION_LIFETIME`(로컬 720분 = 12시간, 기본값 120분). 운영 값은 별도 확인 필요.
- 대리 로그인 화면에서 투표·메시지 전송·요청·프로필 수정은 실제 회원 이름으로 저장된다.
- 저장된 상세페이지 HTML에는 삭제한 오픈 기념 배너가 남아 있을 수 있다.

## 배포 전 필요한 작업

1. `php artisan migrate` (`last_login_at`)
2. `npm run build` (회원 화면 레이아웃·카운트다운·로그아웃 모달·화면 전환 변경)
3. 발표 멘트를 새 기본값으로 쓰려면 편집 화면에서 [기본값으로 되돌리기] 후 저장
4. 운영 `SESSION_LIFETIME`, `APP_ENV=production`(텔레그램 리포트, `?all=1` 제한) 확인

## 검증 상태

프로젝트 정책에 따라 빌드·테스트·린트·문법 검사는 실행하지 않았고 코드를 읽어서만 확인했다. 화면 확인 필요: 대리 로그인(덮어쓰기·읽음 미처리·표시), 체크인 카드 클릭 동작, 행사 상세 남/여 분리와 접속순 정렬, 메시지 모달 필터, 명단 이미지 10명 기준 동작, 접속 마감(로그인 거절·강제 로그아웃·카운트다운 모양), 지속 레이아웃 전환(PC·모바일), 입장 QR이 선택 행사로 연결되는지, 발표 멘트 한글 저장.
