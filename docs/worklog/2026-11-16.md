## 1. 1:1 소개팅 음료 선택

### 최종 동작

| 영역 | 내용 |
|---|---|
| 참가자 | **입장등록**에서만 음료를 고른다. (1:1 행사 + 등록된 음료가 있을 때 필수, 와인파티는 해당 없음) 2열 카드(이모지) 선택 → 입장 전 확인 모달에 "OO 가져다 드릴까요? 등록 후에는 바꿀 수 없어요." 문구 표시. 등록 후 변경 화면 없음. |
| 관리자 설정 | 행사 상세의 "음료 선택" 카드(그날의 인기 TOP3 위). 음료 이름을 입력해 `추가`, 칩을 눌러 삭제, `음료 목록 저장`. 최대 30개, 중복 제거, 순서 유지. |
| 기본 음료 | 1:1 행사 **생성 시** 자동 추가: 아메리카노(ICE/HOT), 물(ICE/HOT), 케모마일(ICE/HOT). `EventDrink::DEFAULT_NAMES`에서 관리. 이미 만든 행사나 생성 후 타입을 1:1로 바꾼 행사에는 자동 추가되지 않는다. |
| 선택 현황 | **행사 상세의 "음료 선택" 카드에서만** 노출. 음료별로 남(파랑)/여(분홍) 2열, 번호표 순, `N호 · M번 테이블`(입장등록 때 배정된 **기준 테이블**, 로테이션으로 바뀌지 않음). 미선택자도 같은 형식. |
| 실시간 | 입장등록(실제/더미) 시 `MemberDrinkChosen` 신호(public 채널 `event-drinks.{eventId}`) 발행 → 행사 상세가 현황 영역과 선택/미선택 뱃지를 다시 불러와 교체. Reverb 필요. |

### 변경 이력(의사결정)

처음엔 하단 nav 탭 + 별도 선택 화면으로 만들었으나, 요청에 따라 **입장등록 선택으로 변경**하고 nav 탭/선택 화면/저장 라우트를 삭제했다. 로테이션 진행 화면 테이블 카드의 음료 표시와 구독 코드, 참여자 표의 음료 뱃지도 요청에 따라 제거했다. (선택 현황은 행사 상세 카드 한 곳)

### DB

- `event_drinks` (신규): `event_id`(FK cascade), `name`, `sort_order`, `(event_id, name)` unique
- `members.event_drink_id` (신규 컬럼): FK `event_drinks.id` `ON DELETE SET NULL`
- 마이그레이션: `2026_11_16_170000_create_event_drinks_table.php`, `2026_11_16_170100_add_event_drink_id_to_members_table.php`
- `data:purge all` 대상에 `event_drinks` 추가. `members` 범위는 행사를 유지하므로 `event_drinks`를 지우지 않는다.

### 주요 파일

- 모델/이벤트: `EventDrink`(신규), `EventRound::drinks()`, `Member::eventDrink()`, `Events/MemberDrinkChosen`(신규)
- 입장등록: `Auth/MemberAuthController`(음료 목록 전달·검증·저장·신호), `Pages/Auth/Register.jsx`(음료 카드, 확인 모달 문구, 자동 입력)
- 관리자: `Rotation/EventController`(저장 엔드포인트, 기준 테이블 맵), `RotationService`(`eventDrinkSync`, 생성 시 기본 음료, 상세 조회 확장), `EventDrinkSaveRequest`(신규), `routes/admin.php`, `eventForm.blade.php`, `_drinkPeople.blade.php`(신규)
- 더미: `RosterService::devSeedRegistrations`가 1:1 더미 회원에 음료를 무작위로 선택시키고, 커밋 후 신호 발행

### 알려진 제약

- 관리자가 음료를 목록에서 지우면 그 음료를 고른 회원의 선택이 `null`이 된다. 참가자가 다시 고를 화면이 없어 음료 없이 남는다. (관리자가 대신 지정하는 기능은 미구현)
- `MemberFactory`는 수정하지 않았다. 더미 입장등록 외 경로로 1:1 회원을 만들 때는 음료가 비어 있다.
- `seating.blade.php` 등에서 Blade `@json([...여러 줄 config()...])`는 파싱 오류(`Unclosed '['`)가 나므로 `{!! json_encode([...]) !!}`를 쓴다.

## 2. 체크인 화면 (`checkin.blade.php`)

- 화면 순서: 헤더·통계 → **체크인 명단 추가(접이식)** → 안내 문구 → 남/여 체크인 목록 → 개발 도구(접이식)
- **테이블별 성비 카드 삭제.** 번호표 입력 모달의 성비 표시는 유지(데이터는 새로고침 때 계속 받아 둔다).
- 명단 추가: 기본 펼침, 접으면 `localStorage`(`rotable.checkin.addRosterCollapsed`)에 저장해 새로고침 후에도 유지. 브라우저 단위(행사별 아님).
- 새로고침 버튼 + 마지막 갱신 시각을 헤더로 이동. 모바일은 전체 폭 `btn-lg`로 다른 버튼과 통일, 태블릿 이상은 한 줄.
- 더미 명단/체크인/입장등록, 기존 테이블 동기화 버튼은 "개발 도구" 접이식으로 이동(권한 조건 그대로).

## 3. 행사 상세 (`eventForm.blade.php`)

- 입장 QR / 전체 매칭 / 매칭 결과 / 메시지 / 요청 / 목록 버튼을 정보 수정 카드 밖의 **별도 버튼 그리드**로 분리. 모두 같은 크기(높이 44px), 모바일 2열 · 태블릿 이상 자동 다열. (행사 생성 화면은 목록 버튼만 헤더에 유지)
- "행사 정보 수정" 카드 접기/펼치기, 상태 기억(`rotable.eventDetail.infoCollapsed`).
- 음료 선택 카드는 TOP3 위로 이동.

## 4. 탭바 (`components/event-tabs.blade.php`)

- 모바일(768px 미만): 행사 선택 한 줄 전체, 탭 3개 동일 폭 3열(라벨 아래 배지), 최소 높이 56px. 태블릿 이상은 기존 유지.
